# W4 comparator study — GitHub Desktop + Postman/Insomnia

Round: `ui-benchmark-1` (worker-4). Comparators: GitHub Desktop (`desktop.github.com`, `docs.github.com` desktop section), Postman (`postman.com`, `learning.postman.com`), Insomnia (`insomnia.rest`, `docs.insomnia.rest` → `developer.konghq.com`). Assigned focus: status honesty and local-execution UX (GitHub Desktop's local-vs-remote state model vs the office's verified / self-reported / UNKNOWN distinction) and request lifecycle UX (Postman/Insomnia collections, request state, response inspection vs the office's request rows and provider-job record).

## 4. Office comparison per dimension

- **Information density — Postman better.** `swipe/worker-4/pm-07-lc-history.txt` shows a header/sidebar/workbench/right-sidebar/footer anatomy where every strip carries state; the office's `live/live-20-settled-office.png` leaves most of the office scene as wallpaper and compresses work state into tiny captions. Baseline weakest evidence: `live/f-20-project-detail.png` — the Requests list gives each row only name, status badge, timestamp and "Research · Test dir 1"; no duration, step count or next action. Postman's response row (status code + ms + kB in `swipe/worker-4/pm-04-lc-requests.png`) shows how much a single row can carry.
- **Navigation model — comparable, slight edge to comparators for depth cues.** Office sidebar grouping (Workspace/Research/Records/System) is clean in `live/f-20-project-detail.png`, and the command palette exists (`empty/empty-command-palette.png`). GitHub Desktop keeps a single mental model (repo bar + Changes/History tabs, `swipe/worker-4/ghd-01-landing.png`); Postman's Ctrl+Shift+P palette matches the office's "Go to…". The office loses a point of confidence because the project-scoped vs global pages relationship ("All projects" chat vs per-project records) needs inference from shots rather than an explicit breadcrumb hierarchy.
- **Queue/status UX — comparators better at the per-item lifecycle.** Postman's per-request History dropdown ("timestamps and the status code the system returned", `swipe/worker-4/pm-08-lc-troubleshoot.txt`) gives every sent request an inspectable lifecycle; the office's expanded row in `live/f-11-attention-panel.png` shows only "Status: ready" + "Provider job: failed" with no per-step timeline, and `live/f-21-request-open.png` shows the request still on the list — the row is a summary, not a history. GitHub Desktop's verb progression (Fetch → Pull → Push in `swipe/worker-4/ghd-06-sync-branch.png`) is exactly what a hop's lifecycle (dispatched → acknowledged → running → settled) could look like.
- **Presence and notifications — office better at intent, Postman better at grouping.** The office's NEEDS YOU panel (`live/f-11-attention-panel.png`) is a genuine routed-attention surface: one item, one reason ("A step failed"), one action ("Open the request to retry or cancel the failed step") — stronger routing than Postman's notifications bell. But Postman's home "Needs your attention" widget groups pending items by kind — join requests, access requests, edit requests, PRs awaiting review (`swipe/worker-4/pm-07-lc-history.txt`) — while the office panel in the baseline shows a single flat entry; how it scales to several items is not evidenced.
- **Status honesty — office better, and it is the office's claim to make loudly.** GitHub Desktop's "Last fetched 2 minutes ago" (`swipe/worker-4/ghd-01-landing.png`) is the best comparator pattern — state plus staleness. The office already beats every comparator on *provenance* labeling: "provider-reported activity" (`live/live-20-settled-office.png`), UNKNOWN vs Idle (`live/live-10-running-office.png`), "Status: ready" vs "Provider job: failed" (`live/f-11-attention-panel.png`), and History's "does not perform a new chain verification" + "Office observation is not provider attestation" disclaimers (`live/live-24-history.png`). What the office lacks is the *freshness* half: no "reported N seconds ago" / "last verified" timestamp is visible on agent or job state in any baseline shot — GitHub Desktop's pairing of state with fetch age is the gap.
- **Empty/loading/error states — comparable; office is honest, comparators are more actionable.** Office empty states are explicit and correctly non-fatal ("No research branches are recorded", `live/f-11-attention-panel.png`; "No activity recorded" tab chip). Postman goes further on errors: a failed send yields a detailed message, a Console link and "Debug with AI" (`swipe/worker-4/pm-08-lc-troubleshoot.txt`); the office's "A step failed" row + NEEDS YOU entry routes to retry/cancel but surfaces no error detail or log link inline — detail lives behind "Open request".
- **Accessibility — no winner; all thin in captured evidence.** GitHub Desktop documents a full keyboard map (`swipe/worker-4/ghd-10-history.png`); the office has "Go to…" but no captured focus/screen-reader affordances, and its small secondary text ("Idle · no open provider work", `live/live-20-settled-office.png`) plus low-contrast muted labels (`live/live-10-running-office.png` STATUS column) are a risk visible in the shots.

## 5. Proposed revision packet seeds (ranked by expected impact)

Proposals only — no roadmap edits, no product changes. File scope is rough and renderer-side unless noted; shared-type/IPC changes are organizer-owned.

1. **"Last verified / reported Ns ago" freshness stamps on all provider-derived state.** Problem: the office labels provenance ("provider-reported activity") but never freshness; GitHub Desktop's "Last fetched 2 minutes ago" pairs state with age (`swipe/worker-4/ghd-01-landing.png` vs `live/live-20-settled-office.png`, `live/live-10-running-office.png`). Scope: `app/src/renderer/office-scene.tsx` + `status.ts` + `agents.tsx` status chips + `format.ts` (relative-time helper); data likely already on the projection (receipt/observation timestamps) — confirm against `core/jobs.ts`/store projection, no schema change expected.
2. **Per-request job timeline in the expanded row/drawer.** Problem: a request row expands to two bare lines ("Status: ready", "Provider job: failed", `live/f-11-attention-panel.png`) with no lifecycle; Postman's per-request History lists every send with timestamp + outcome (`swipe/worker-4/pm-08-lc-troubleshoot.txt`). Add a compact timeline of the request's hops/jobs — minted → dispatched → provider-observed → settled/failed — with timestamps and provenance tag each. Scope: `app/src/renderer/projects.tsx` (expanded row) or the request drawer in `queue.tsx`; read model from `core/jobs.ts`/store events — verify which events already persist before scoping.
3. **Group NEEDS YOU items by action kind.** Problem: the panel shows one flat entry (`live/f-11-attention-panel.png`); Postman's "Needs your attention" groups pending items by role/kind so the user triages by shape, not arrival order (`swipe/worker-4/pm-07-lc-history.txt`). Group as e.g. "Failed steps", "Decisions waiting", "Reviews open". Scope: the attention-panel component (likely `shell-widgets.tsx`/`queue.tsx`) — pure renderer regroup of existing attention data.
4. **Provenance chips on records beyond the live view.** Problem: honesty labels exist in the office scene and History disclaimers but not on the request rows, agent table cells, or artifact entries themselves; Insomnia's storage table shows per-project locality is a first-class field (`swipe/worker-4/ins-05-storage.txt`). Add small provenance tags (office-observed / provider-reported / user-imported) wherever a record is rendered — request rows (`live/f-20-project-detail.png`), agent status (`live/live-10-running-office.png`), history entries (`live/live-24-history.png`). Scope: `status.ts` (badge variants) + the row components in `projects.tsx`, `agents.tsx`, `history.tsx`.
5. **Raw transport/console view per job (labeled office-observed).** Problem: debugging a failed step requires trusting summaries; Postman's Console exposes the raw response and locally-stored request log with stated bounds (`swipe/worker-4/pm-08-lc-troubleshoot.txt`). Surface each provider job's office-observed events (spawn, receipts, exit) in an expandable log on the request/job view, labeled "office-observed, not provider attestation" to preserve the boundary. Scope: `activity.tsx`/`job-outputs.ts` + a row affordance; records should already exist in the event stream.
6. **Explicit "Check now" refresh affordance on agent/provider state.** Problem: GitHub Desktop separates inspecting remote state (Fetch) from mutating local state (Pull) (`swipe/worker-4/ghd-06-sync-branch.txt`); the office polls/observes passively, and there is no user-visible "verify now" that also stamps the freshness from seed 1. Scope: `agents.tsx` row action + a read-only IPC (organizer-owned surface — flag before implementing); lowest rank because it touches main-process surface.

## 6. Gaps and honesty notes

- All comparator evidence is public marketing/docs captured headless (method (a)); **no authenticated product UI was exercised**. Scores that depend on in-app behavior (live queue updates, notification delivery, screen-reader behavior) are inferred from docs and are labeled as such in the scorecard; Postman/Insomnia "presence" and "accessibility" scores carry the most inference.
- GitHub Desktop UI evidence comes from the marketing hero (`swipe/worker-4/ghd-01-landing.png`) and screenshots embedded in docs (`ghd-06-sync-branch.png`) — real product shots, but chosen by the vendor; no install was performed.
- Two capture URLs 404'd and were re-pointed (pm-05 → `…/response-data/responses`; insomnia docs moved to `developer.konghq.com`); `manifest.json` records originals. Insomnia get-started path was not found (`ins-06` absent) — coverage gap noted, not guessed.
- Baseline screenshots show a font-glyph rendering artifact (dropped letters like "Volatilty", "ndependent") and Korean-locale timestamps ("9월 30일 오전 4:35") inside English UI — flagged as observations on the capture, not assumed product defects; the locale mixing may be a real i18n nit worth a follow-up.
- Nothing was purchased; no MCP/partial-report source was needed (methods (b)/(c) unused); no `app/`, `docs/ROADMAP.md` or out-of-scope file was touched. All swipe artifacts are outside Git and must not be committed.
