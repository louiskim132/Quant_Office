# S2 / LR-16b — prepared subscription-isolation design

Current status (2026-10-02): implementation landed as `e4494fe` / merge `070c297`; real official provider sign-ins and isolated subscription dispatch acceptance remain incomplete. The 2026-10-02 user request excludes legal review and reopens free technical revisions. The publication candidate adds durable isolation intent/credential failure handling and an explicit scratch dispatch operation to the existing user-assisted harness. Isolation remains off in real workspaces under D-6 until real acceptance. The design text below preserves the original implementation contract; it does not represent counsel approval.

Use the QRO-Agent token's `os.userInfo().homedir` and username inside `agent-host.cjs` to derive its profile environment. Set USERPROFILE, HOMEDRIVE/HOMEPATH, APPDATA and LOCALAPPDATA from that account. Retain the current machine-only PATH and environment allowlist. Never copy the office user's provider credentials or profile variables. Keep `subscriptionEnvironment` scrubbing provider keys and ambient OAuth overrides. No token-import alternative is selected.

Sign-in must run visibly as QRO-Agent through each installed provider's official login flow. Installed help confirms `codex login`, Claude's own login flow and `devin auth login`. The same host must perform subsequent status/catalog observations. Attach the host Windows identity and credential context to those observations; fresh dispatch must require both the expected host account and the exact provider account bound to the seat. An office-user status response cannot satisfy an isolated-account check.

| Context | Fresh agent-account identity | Dispatch result |
| --- | --- | --- |
| Isolation off | Not applicable | Existing subscription checks apply |
| Isolation on | Absent, stale, unknown or mismatched | Refuse; direct user to agent-account sign-in |
| Isolation on | Matches Windows host and bound provider identity | Eligible after transport and legal gates pass |
| Any | Ambient provider key/token override | Scrub; never silently change billing mode |

Acceptance must use a scratch QRO_USER_DATA_DIR, the standard named roster, and the provider's own sign-in. Verify whoami=qro-agent, denial of access to the office user's profile, correct output hashes, whole-tree cancellation and restart non-duplication for Devin, Claude and Codex. Password rotation/UAC/sign-in were not run in this revision. Existing v1 API-key acceptance is not subscription acceptance.

Before implementation, resolve CLI auto-update behavior for each installed version. Do not invent a disable-update flag. L2 must supply a readable per-machine runtime and provider binaries without exposing the office user's writable profile. The host currently omits profile variables, while `LocalCliExecAdapter` refuses subscription dispatch under isolation; both must change together with the fresh isolated-account observation path and Settings UI.
